# Interactive visitor demo

Public visitors can now run the existing trend/naive models, import private CSVs,
compare backtests and replay saved experiments without a continuously running backend.
Provider credentials and snapshot refresh remain in GitHub Actions. Provider sync buttons
and public API write endpoints remain protected. No new hosting account or service is used.

## Visitor walkthrough

1. Open Overview and select a published asset.
2. Choose trend or naive and horizon 1, 7, 14 or 30 observations.
3. Click Run experiment; the browser computes walk-forward evaluation and forecast.
4. Inspect the chart, MAE, baseline MAE and residual band.
5. Open Experiments; browser runs carry a "This browser" label and B- identifier.
6. Replay recomputes from the original immutable dataset. Saved browser stock runs also
   retain the published exchange-calendar dates for replay after snapshots change.
7. In Data pipeline, import a date,close CSV for an asset. No file or observations are uploaded.
8. Run an experiment on the imported dataset. Fundamentals remain the shared published facts.
9. Use published data returns the selected asset to the public dataset; saved runs remain.
10. Clear browser demo data removes this app's imported datasets and saved browser runs.

Manual production QA: test steps above on the deployed site and reload to verify persistence.
In DevTools Network, import/run/replay must not issue POST requests. GET requests read public
snapshots; browser CSV prices never form part of request URLs or bodies.
Try an invalid CSV; previous valid data must remain. Try another browser profile; imports
and history should be absent there.

## Data and numerical rules

CSV: at most 2 MB, 100–10,000 input observations; exact lowercase date and close headers.
Quoted fields, escaped quotes, UTF-8 BOM and CRLF are accepted. Dates are sorted and duplicate
dates use the last row. Dates must be valid YYYY-MM-DD; closes finite and positive.
Additional columns are ignored. Currency/adjustment/frequency of imported prices are unverified.

Imported CSV forecasts use calendar-day labels, matching the existing Python CSV importer.
Published XNYS forecasts reuse dates from the precomputed 30-observation snapshot (including
holidays). Published forex uses weekday UTC labels; BTC uses calendar UTC dates. These are
observation horizons, not a guarantee of calendar-day duration.

The engine implements the Python rolling 30-observation log-linear model, last-price baseline,
chronological walk-forward backtest, and empirical 10–90% residual band. The band remains
exploratory and uncalibrated. No model training service or trading execution is added.

Offline tests compare 32 cases generated by backend/server.py: four calendars, both models,
four horizons, constant data with zero baseline error, and varying series. Numeric tolerance
is 1e-10 relative/absolute; forecast dates and evaluation endpoints must match exactly.
Regenerate references after deliberate model changes using:

    .venv-market\Scripts\python.exe backend\export_browser_fixtures.py

## Persistence and limits

Up to 20 browser experiments and their required datasets are kept in localStorage under
signal-browser-demo-v1. They do not sync between devices, accounts, browsers or origins.
Clearing site data removes them. Storage limits/private browsing can prevent saving; the UI
reports this instead of claiming a save succeeded. Quota errors preserve the prior stored state.
There is no multi-user backend database or cross-device history in this version.

Production uses browser experiments; npm run dev continues to use the local Python API unless
NEXT_PUBLIC_READ_ONLY=true is explicitly set for testing. Existing local SQLite data is untouched.
The EURUSD fundamental provider issue is separate and remains for later diagnosis.
